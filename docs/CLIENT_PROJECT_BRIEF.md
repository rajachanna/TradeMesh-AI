# Custom Trading Automation — Client Project Brief

This brief is for anyone considering a bespoke MT5, IBKR, CEX/DEX or TradingView automation project.

## What I can help scope

- Broker or exchange API integration and connector prototypes
- TradingView signal ingestion, validation and order routing
- Demo/paper execution and order status reconciliation
- Exposure limits, position sizing rules and operator alerts
- Trading dashboards, logs, historical reporting and deployment workflows

**Not claimed by TradeMesh AI v0.1:** ready-made IBKR, MT5, DEX or live execution adapters, validated investment returns, performance guarantees or regulated investment advice.

## A clear project definition

Please provide:

| Question | Example |
| --- | --- |
| Broker / exchange / account environment | IBKR paper, MT5 demo, crypto exchange sandbox |
| Instruments and market type | XAUUSD CFD, stock, crypto spot, futures |
| Input signals | TradingView webhook, Pine Script, Python strategy |
| Risk rules | Size formula, max daily loss, exposure cap, kill switch |
| What counts as success? | Successful demo trade, broker-confirmed fill, reproducible logs |
| Delivery requirements | Source code, Docker setup, test report, video, documentation |

## Suggested delivery milestones

1. **Architecture & requirements:** agreed inputs, outputs, security boundaries and test cases.
2. **Working simulation / sandbox integration:** documented behavior with deterministic scenarios.
3. **Acceptance verification:** test results and observed broker execution/latency, when applicable.
4. **Optional production hardening:** credentials, monitoring, failure recovery and security review.

No live execution or account profitability is guaranteed. Scope, pricing and timeline should be estimated after the broker, strategy and environment are known.
